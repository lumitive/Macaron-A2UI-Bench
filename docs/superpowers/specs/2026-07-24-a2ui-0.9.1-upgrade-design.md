# A2UI Bench Protocol Upgrade Design: v0.8 → v0.9.1

> **Follow-up:** Phase 1.5 “Macaron-extended on 0.9.1” is superseded by **LUMI-extended (Track 2)** — see `2026-07-25-lumi-a2ui-bench-product-design.md` and `plans/2026-07-25-lumi-catalog-0.9.1.md`.

**Date:** 2026-07-24  
**Status:** Phase 1 implemented; Phase 1.5 → LUMI Track 2  
**Repo:** LUMI-A2UI-Bench (historical path may still be Macaron-A2UI-Bench)  
**Target protocol:** A2UI **v0.9.1** (Current). **v1.0** is explicitly out of Phase 1 scope.

## 1. Problem

The benchmark is hard-pinned to A2UI **v0.8** (legacy): message keys (`beginRendering`, `surfaceUpdate`, …), key-wrapped components (`{"Text":{…}}`), typed data wrappers (`valueString`, `literalString`), Macaron-extended catalog + standard catalog divergence, and `@a2ui/lit@0.8.x` for optional visual eval.

Upstream has moved: **v0.9 / v0.9.1** introduced a Prompt-First redesign; **v1.0** is a release candidate on top of 0.9.x. The bench must upgrade in a controlled way so JSON L1–L3 and visual/VLM evaluation can score **0.9.1-native** model output, while retaining **0.8 as a historical comparison stack**.

## 3. Protocol delta metrics (0.8 → 0.9.1)

Primary source: [v0.8 → v0.9 evolution guide](https://a2ui.org/specification/v0.9-evolution-guide/). v0.9.1 is a minor refinement of v0.9 (MIME type `application/a2ui+json`, `surfaceId` uniqueness among active surfaces). Message `version` accepts both `"v0.9"` and `"v0.9.1"`. v1.0 deltas are Phase 2 foreshadowing only.

| Metric | v0.8 (current bench) | v0.9.1 (Phase 1 target) | Bench impact |
|--------|----------------------|-------------------------|--------------|
| Philosophy | Structured Output First | Prompt-First / in-context schema | Rewrite generation + judge prompts |
| Version envelope | No required `version` | Per-message `version` (`v0.9` / `v0.9.1`) | Parser + L1 |
| Create surface | `beginRendering` + `root` + optional `styles` | `createSurface` + required `catalogId`; root component **id must be `root`** | Lint, guides, depth history |
| Update components | `surfaceUpdate` + `{ "Text": { props } }` | `updateComponents` + flat `"component": "Text"` | Lint, prompts, renderer |
| Update data | `dataModelUpdate` + `contents[]` with `valueString` / … | `updateDataModel` + JSON `value` object | L1 data rules, judges |
| Binding | `{literalString}` / `{path}` wrappers | Native literals **or** `{path}`; `formatString` for interpolation | Generation + validation |
| Choice UI | `MultipleChoice` | `ChoicePicker` + `variant` | Catalog, themes, gold |
| Button | `primary: bool`; context as KV array | `variant` enum; context as object map | Guides + lint |
| TextField | `text` / `textFieldType` | `value` / `variant`; `checks` | Catalog mapping |
| Layout props | `distribution` / `alignment` | `justify` / `align` | Catalog / examples |
| Modal / Tabs | `entryPointChild` / `contentChild` / `tabItems` | `trigger` / `content` / `tabs` | Catalog |
| Rules artifact | Mostly inlined in bench prompts | Catalog rules text (filename discovered at vendor time) alongside schema | Prompt assembly |
| Renderer pin | `@a2ui/lit` 0.8.x | 0.9.1-compatible Lit stack via **`v0_9` export** | `render_v091` |
| → v1.0 (Phase 2 only) | — | `theme`→`surfaceProperties`, `actionResponse` / `callFunction`, inline components in `createSurface`, etc. | Future `protocol/v1_0` |

### Current bench exposure (why upgrade is large)

- **Validators:** `vendor/a2ui_demo` lint assumes four 0.8 action keys and key-wrapped components.
- **Prompts:** `evaluate_api_model.py` minimal guide + L2/L3 prompts use 0.8 shapes and Macaron-leaning names (`Label`, `SelectionList`, …).
- **Judge helpers:** `_a2ui_summary` and `_build_component_schema_context` are 0.8-shaped today and must become protocol-aware.
- **Renderer:** `render/` vendors 0.8 Lit/web_core (standard catalog only).
- **Visual gate:** `visual_eval.py` hardcodes root `render_check` (0.8). On the 0.9.1 path it must use the protocol stack’s `render_check` or valid 0.9.1 UIs are filtered out.
- **Data:** ~300 eval / ~600 source tasks; depth tasks embed **0.8** `gt_a2ui` (~586 messages in eval_300). Top-level tasks have no `gt_a2ui`. Depth history today is already text-only (`running_context`); strip remains required hygiene so gold is never injected later.
- **Dual catalog risk today:** prompts/lint allow Macaron types that the shipped Lit renderer cannot render.

## 4. Architecture

### 4.1 Parallel stacks

| Unit | Role |
|------|------|
| `protocol/v0_8/` | Existing 0.8 schema/catalog/lint entrypoints (migrate or thin-wrap current `vendor/a2ui_demo`) |
| `protocol/v0_9_1/` | Vendored official 0.9.1 envelope + basic catalog + rules; new lint + `render_check` API |
| `evaluate_api_model.py` | Shared orchestrator; `--protocol-version {0.8,0.9.1}` selects guide/lint/parse/judge schema injection |
| `render/` | Keep 0.8 Lit harness for comparison runs |
| `render_v091/` | New 0.9.1 renderer harness (build, ingest, screenshot) using Lit **`v0_9`** API |
| `visual_eval.py` / `visual_compare_models.py` | Select renderer base URL, **stack `render_check`**, and VLM copy by protocol version |
| `data/` | Shared task semantics; 0.9.1 path strips `episode_turns[].gt_a2ui` |

### 4.2 Runtime selection

- Default after cutover: `PROTOCOL_VERSION=0.9.1` (CLI `--protocol-version`, env, `run_benchmark.sh`).
- Comparison: `PROTOCOL_VERSION=0.8` keeps current behavior.
- **Invariant:** one run uses exactly one protocol stack end-to-end (no 0.9.1 prompt + 0.8 lint / 0.8 `render_check`).
- Cross-version score comparison = two independent runs (or CI matrix jobs), results under `results/<protocol_version>/` with `protocol_version` in the manifest.

### 4.3 Phases

1. **Land parallel 0.9.1 stack** (protocol + lint + prompts + `render_v091` + visual wiring). Default may remain 0.8 until validated.
2. **Switch defaults** to 0.9.1; strip `gt_a2ui` on 0.9.1 depth path; update README / scripts / CI.
3. **Retain 0.8** indefinitely for historical comparison (smoke + optional full eval).
4. **Phase 1.5:** Macaron-extended catalog on 0.9.1.
5. **Phase 2:** v1.0 candidate stack (new directory), separate design.

## 5. Evaluation contracts

```text
Task JSON → build_messages(protocol) → Model → parse_a2ui(protocol)
                                              ├─ L1 lint(protocol)
                                              ├─ L2/L3 judge(protocol; protocol-aware summary + schema context)
                                              └─ optional visual: stack.render_check → screenshot → VLM
```

| Layer | 0.8 (retained) | 0.9.1 (new default) |
|-------|----------------|---------------------|
| Generation guide | Current minimal/Macaron-leaning guide | Official basic catalog + rules; flat components; native literals; `catalogId` = locked basic URI |
| Parse | Four 0.8 action keys | Envelope `version` + `createSurface` / `updateComponents` / `updateDataModel` / `deleteSurface` |
| L1 | Existing `a2ui_lint` levels 1–4 | New lint vs 0.9.1 schema; require `catalogId`; require `id=root`; basic catalog types only in Phase 1; diagnostic codes use `STRUCT_` / `REF_` / `DATA_` / `LINT_` prefixes |
| `render_check` | Current Macaron/0.8 rules | Rewrite for 0.9.1 renderability (no 0.8-only rules such as `literalArray` on SelectionList) |
| L2/L3 | Current judge prompts + 0.8 `_a2ui_summary` / schema context | Versioned judge prompts; `_a2ui_summary` understands 0.9.1 keys; inject stack `component_schema_context` |
| Visual | `render/` + root `render_check` | `render_v091/` + **stack** `render_check`; VLM rubrics use 0.9.1 terms |
| Depth history | May copy `gt_a2ui` onto task samples (not injected into text history today) | **Strip/ignore `gt_a2ui`**; keep dialogue/task fields only |

Results must land under `results/<protocol_version>/` and record `protocol_version` so 0.8 and 0.9.1 scores never overwrite each other silently.

## 6. Error handling

| Case | Behavior |
|------|----------|
| Missing/mismatched `version` vs selected protocol | L1 fail with `STRUCT_PROTOCOL_VERSION_MISMATCH`. **Do not call** L2/L3 judges or take screenshots; still record **floor** L2/L3 scores with note `penalized: L1 failed` (same aggregation policy as today’s `evaluate_api_model.py` — do not invent skip-from-denominator behavior in Phase 1). Visual marked not-run / failed with reason. |
| 0.8 shapes on 0.9.1 path (`beginRendering`, `literalString`, `valueString`, …) | Protocol error `STRUCT_LEGACY_0_8_SHAPE` (optional “looks like 0.8” hint); **no silent auto-convert** |
| Unknown component vs active catalog | L1 structural error (Phase 1: Macaron names fail on 0.9.1 basic) |
| Missing `catalogId` or missing `id=root` | L1 error (`STRUCT_MISSING_CATALOG_ID` / `REF_MISSING_ROOT`) |
| `render_check` failure | Same policy as today: floor-penalize L2/L3 (do not call judges) / skip visual capture with recorded reason |
| Screenshot / VLM failure | Mark visual failed for sample; JSON L1–L3 already written remain valid |
| Depth `gt_a2ui` on 0.9.1 | Strip at load; do not inject into model history |
| `--prompt-mode full` + `0.9.1` | Hard error (0.8-only full schema path); use `minimal` with stack guide |

## 7. Migration order

1. Vendor official 0.9.1 schema / basic catalog / rules into `protocol/v0_9_1/` (include `$ref` deps such as `common_types.json` as needed).
2. Implement 0.9.1 lint, `render_check`, generation + judge prompts.
3. Wire `--protocol-version` in `evaluate_api_model.py` (default may stay `0.8` until step 6); make `_a2ui_summary` + judge schema context protocol-aware.
4. Create `render_v091/` with build + message ingest + screenshot path (inspect real Lit `v0_9` API; commit `package-lock.json`).
5. Point visual scripts at versioned renderer **and stack `render_check`**; align VLM prompts.
6. Flip defaults to `0.9.1`; strip depth `gt_a2ui` on that path; update docs/scripts/CI including `run_benchmark.sh` `PROTOCOL_VERSION` / `RENDER_URL` / results nesting.
7. Keep 0.8 stack + CI smoke for comparison.
8. Phase 1.5 / Phase 2 as separate scoped work.

## 8. Testing strategy

| Level | What |
|-------|------|
| Unit | 0.9.1 fixtures: valid UI; missing root; version mismatch; 0.8-shaped payload rejected; catalogId lock; `_a2ui_summary` / visual URL / stack `render_check` helpers |
| Contract | Same fixture must not pass both protocol linters incorrectly (0.8 fixture fails 0.9.1; 0.9.1 fixture fails 0.8) |
| CI smoke | **0.9.1:** compile + pytest protocol fixtures + small `prepare_eval_split` + `render_v091` build (`npm ci` needs lockfile). **0.8:** keep existing Python/render smoke |
| PR gate | 0.9.1 green required for protocol/eval/render_v091 changes; 0.8 smoke protects comparison stack (path filters allowed for docs-only) |
| Manual / periodic | Small API + visual runs; optional 0.8 vs 0.9.1 score distribution comparison (not default CI) |

## 9. Non-goals (Phase 1)

- Implementing or scoring **v1.0** (`actionResponse`, `callFunction`, `surfaceProperties`, …).
- Auto-converting 0.8 model output to 0.9.1 for scoring.
- Regenerating or mechanically rewriting depth `gt_a2ui` gold (deferred).
- Shipping Macaron-extended catalog on 0.9.1 (Phase 1.5).
- Deleting the 0.8 codepath or `render/`.
- Accepting CLI alias `0.9` for `0.9.1`.

## 10. Success criteria (Phase 1 done)

- `--protocol-version 0.9.1` runs generate → L1 → L2/L3 on sampled tasks using basic catalog shapes and the locked basic `catalogId`.
- `render_v091` builds; visual/VLM path ingests 0.9.1 messages end-to-end using **stack** `render_check` (not root 0.8 `render_check.py`).
- Default scripts/docs/CI target 0.9.1; `run_benchmark.sh` passes protocol version and matching render URL / results subdir.
- `--protocol-version 0.8` still runs for comparison; 0.8 assets remain in-tree.
- Depth tasks on 0.9.1 do not depend on embedded 0.8 `gt_a2ui`.
- Results are partitioned under `results/<protocol_version>/` and tagged with `protocol_version`.
