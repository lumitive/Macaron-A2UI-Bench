# A2UI Bench v0.9.1 Upgrade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a parallel A2UI **v0.9.1** evaluation stack (JSON L1–L3 + full visual/VLM) beside retained **v0.8**, then switch defaults to 0.9.1 without deleting 0.8.

**Architecture:** Versioned protocol packages (`protocol/v0_8`, `protocol/v0_9_1`) and renderers (`render/`, `render_v091/`) selected by `--protocol-version` / `PROTOCOL_VERSION`. One run uses exactly one stack. Results land under `results/<protocol_version>/`.

**Tech Stack:** Python 3.12, `openai`, `jsonschema`, `pytest`; Node 20, Vite, `@a2ui/lit` (upstream `v0_9` export for 0.9.1 messages); GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-07-24-a2ui-0.9.1-upgrade-design.md`

## Global Constraints

- Target protocol: **v0.9.1** only for Phase 1 (not v1.0).
- Catalog Phase 1: official **basic** catalog only (no Macaron extensions on 0.9.1).
- Keep **0.8** stack forever for comparison; do not delete `vendor/a2ui_demo` or `render/`.
- No silent 0.8→0.9.1 auto-conversion of model output.
- On 0.9.1 path: strip/ignore `episode_turns[].gt_a2ui` (do not inject 0.8 gold into history).
- Diagnostic code prefixes for L1 mapping must remain `STRUCT_` / `REF_` / `DATA_` / `LINT_` so `evaluate_l1_scores` keeps working.
- Upstream pin: record SHA in `protocol/v0_9_1/UPSTREAM_PIN.txt` when vendoring (use `a2ui-project/a2ui` `main` at vendor time; known good reference at plan write: `d4723f29254520e1214d5004cb555d83eaafb828`).
- CLI values: exactly `0.8` and `0.9.1` (no `0.9` alias in Phase 1).
- Results layout: `results/0.8/...` and `results/0.9.1/...` (protocol version segment required).
