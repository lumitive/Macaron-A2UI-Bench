## Findings

### R1 — Visual path still hardcodes 0.8 `render_check`
- **Severity:** blocker
- **Doc:** plan (Task 7) / both (success criteria visual E2E)
- **Location:** Plan Task 7; Spec §5 Visual / §10 success criteria
- **Attack:** `visual_eval.py` does `from render_check import render_check` and re-runs it when selecting screenshot targets (`_make_single_turn_target`, `_make_depth_step_targets`). Task 7 only changes default URL / VLM copy. On `--protocol-version 0.9.1`, valid 0.9.1 messages will fail 0.8 rules (`beginRendering`, key-wrapped components, Macaron `literalArray`, etc.) and visual/VLM will systematically empty out — contradicting “full render/visual/VLM upgrade”.
- **Suggested fix:** Task 7 must resolve `get_protocol_stack(...).render_check` and use it in both target builders; add a unit test that a minimal 0.9.1 fixture is not filtered by 0.8 rules. Mirror for `visual_compare_models.py` via shared helper.

### R2 — `_a2ui_summary` remains 0.8-only; L2/L3 judges get empty summaries
- **Severity:** high
- **Doc:** plan (Task 4/5 missing) / both
- **Location:** `evaluate_api_model.py` `_a2ui_summary`; Plan Task 5 judge wiring
- **Attack:** `_a2ui_summary` only recognizes `surfaceUpdate` / `dataModelUpdate` / `beginRendering` / `deleteSurface` and key-wrapped component types. 0.9.1 `createSurface` / `updateComponents` / `updateDataModel` yield near-empty `{a2ui_summary}` even if `l2_judge_v091.txt` exists. Judge quality collapses without a plan step.
- **Suggested fix:** Explicit Task 5 (or 4) step: extend `_a2ui_summary` for flat `"component"` + 0.9.1 action keys; keep 0.8 branches.

### R3 — Spec §6 says “skip L2/L3/visual” on version mismatch; code penalizes with floor scores
- **Severity:** high
- **Doc:** spec
- **Location:** Spec §6 Error handling row “Missing/mismatched version”
- **Attack:** Current `evaluate_api_model` does **not** skip L1-fail / render_check-fail from L2/L3 denominators; it assigns floor scores (`penalized: L1 failed` / `penalized: render_check failed`) so means are not survivor-biased. Spec wording “skip L2/L3/visual” invites a behavioral regression if implementers follow the spec literally.
- **Suggested fix:** Rewrite §6 to: do not call live judges/screenshots; record floor L2/L3 (and N/A or failed visual) consistent with current policy. Do not invent skip-from-denominator semantics in Phase 1.

### R4 — Spec diagnostic code `PROTOCOL_VERSION_MISMATCH` lacks required L1 prefix
- **Severity:** high
- **Doc:** both (spec vs plan contradiction)
- **Location:** Spec §6; Plan Task 3 codes `STRUCT_PROTOCOL_VERSION_MISMATCH`
- **Attack:** `evaluate_l1_scores` maps only `STRUCT_` / `REF_` / `DATA_` / `LINT_` prefixes. A bare `PROTOCOL_VERSION_MISMATCH` still zeros all dims when any error exists (so not a silent pass), but leaves the code unmapped and contradicts plan/tests. Implementers copying the spec alone emit wrong codes.
- **Suggested fix:** Spec §6 must use `STRUCT_PROTOCOL_VERSION_MISMATCH` (plan is source of truth for code strings).

### R5 — Spec “Open follow-ups” still lists decisions the plan already locked
- **Severity:** medium
- **Doc:** both
- **Location:** Spec §11 vs Plan Global Constraints
- **Attack:** Plan locks: UPSTREAM_PIN / SHA reference, CLI exactly `0.8`/`0.9.1` (no `0.9` alias), results `results/0.8` and `results/0.9.1`. Spec §11 still lists these as open — agents reading the spec may re-litigate or diverge.
- **Suggested fix:** Move locked items into Spec §2 Decisions (or close them in §11 with pointers to plan constraints). Keep only truly deferred items (Phase 1.5 list, Phase 2).

### R6 — Plan Task 1 Interfaces name mismatch: `judge_prompt_suffix` vs `component_schema_context`
- **Severity:** medium
- **Doc:** plan
- **Location:** Task 1 Interfaces bullet vs `ProtocolStack` dataclass snippet
- **Attack:** Same task defines two different field names. Implementers / tests will disagree on the dataclass shape.
- **Suggested fix:** Use one name everywhere — prefer `component_schema_context` (matches code sample).

### R7 — `full` prompt-mode + 0.9.1 can silently serve 0.8 `system_prompt_full.txt`
- **Severity:** medium
- **Doc:** plan
- **Location:** Task 5 “full may still 0.8-only — raise clear error or fall back to stack guide”
- **Attack:** Soft fallback to 0.8 full prompt on 0.9.1 violates the one-stack invariant and “no 0.9.1 prompt + 0.8 lint” spirit. Ambiguous “or” invites the wrong choice.
- **Suggested fix:** Hard error only: `--prompt-mode full` + `--protocol-version 0.9.1` raises; Phase 1 supports `minimal` (stack guide) only unless a 0.9.1 full prompt is authored.

### R8 — `prompts/__init__.py` versioned loader API underspecified
- **Severity:** medium
- **Doc:** plan
- **Location:** Task 4 “Modify prompts/__init__.py”; Task 5 “load l2_judge_v091.txt”
- **Attack:** Current loaders are parameterless `load_l2_judge_prompt()` / `load_l3_judge_prompt()`. Plan says modify but does not define the new signature or how eval selects templates — easy to leave dead files.
- **Suggested fix:** Specify `load_l2_judge_prompt(protocol_version: str = "0.8")` (or dedicated `*_v091` helpers) and require Task 5 to call them.

### R9 — Spec PR-gate “path filters” not reflected in Task 9 CI
- **Severity:** low
- **Doc:** both
- **Location:** Spec §8 PR gate; Plan Task 9
- **Attack:** Spec allows path filters for docs-only; Task 9 makes both render jobs always run with no `paths:` / conditional. Not wrong for safety, but spec/plan disagree on expected CI behavior.
- **Suggested fix:** Either drop path-filter language from spec §8 for Phase 1, or add an explicit Task 9 note: “no path filters in Phase 1; both smokes always run”.

### R10 — Task 2 invents `catalog_id="macaron-a2ui-demo-0.8"` with no codebase source
- **Severity:** low
- **Doc:** plan
- **Location:** Task 2 `build_stack()` sample
- **Attack:** 0.8 path today has no such URI; fake ID may be written into manifests and confuse comparison. Harmless if unused, but undocumented.
- **Suggested fix:** Use a clearly local sentinel (e.g. `legacy-0.8` / `vendor/a2ui_demo`) and note it is not an upstream catalog URI.

### R11 — Success criteria / Task 7 omit visual `render_check` stack selection (compound with R1)
- **Severity:** medium (doc completeness; same root as R1)
- **Doc:** spec §10
- **Location:** Success criteria bullet on `render_v091` visual path
- **Attack:** “visual/VLM path ingests 0.9.1 messages end-to-end” is underspecified without mentioning protocol-aware prefilter. Easy to mark Task 7 done while visual still broken.
- **Suggested fix:** Add success criterion: visual selection uses the active protocol stack’s `render_check`.

### R12 — Plan never mentions updating `_build_generation_guide` / removing dual sources of truth for guides
- **Severity:** low
- **Doc:** plan
- **Location:** Task 5 vs existing `A2UI_MINIMAL_GUIDE` in `evaluate_api_model.py`
- **Attack:** Task 2 copies guide into `protocol/v0_8/guides.py`; Task 5 says use `stack.generation_guide`. Residual `A2UI_MINIMAL_GUIDE` + `_build_generation_guide(prompt_mode)` can drift unless Task 5 explicitly deletes/redirects the old path.
- **Suggested fix:** Task 5 step: replace `_build_generation_guide` usage with stack guide (minimal) / hard-error (full+0.9.1); mark old constant as deprecated or moved.
